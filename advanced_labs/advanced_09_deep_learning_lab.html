Advanced Module A9 — Deep Learning¶

Lab: training a simple MLP in PyTorch¶

Course: Quantitative Research Methods
Instructor: Prof. Dr. Christoph Weisser
Source: James, Witten, Hastie, Tibshirani & Taylor (2023), An Introduction to Statistical Learning, with Applications in Python, Springer. Companion code at statlearning.com.

Goal. Build, train and evaluate a small MLP on the Default data in PyTorch; check the deck’s parameter counts in code; and ask what the network actually buys over logistic regression. Requires pip install torch.

Setup¶

Run this cell once. The ISLP package can be installed with pip install ISLP. As an alternative, the same data sets are available as CSVs in the workspace’s ALL CSV FILES - 2nd Edition folder.

Google Colab: this notebook also runs on Colab out of the box — the setup cell below installs any missing packages and downloads the data automatically.

1. Data¶

Default is 10,000 credit-card customers, of whom only about 3% actually default. Two things have to happen before a network sees data like this:

  • Standardise the predictors. Gradient descent uses one learning rate for every weight, so a predictor measured in tens of thousands (income) and one measured in hundreds (balance) would effectively get different step sizes. The scaler is fitted on the training split only — fitting it on everything leaks test information into the scaling.

  • Encode student as 0/1, because a network multiplies its inputs and cannot multiply the string 'Yes'.

Default = load('Default')
Default['student_d'] = (Default['student'] == 'Yes').astype(int)
y = (Default['default'] == 'Yes').astype(int).values
X = Default[['balance', 'income', 'student_d']].values.astype('float32')
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=0)
scaler = StandardScaler().fit(Xtr)
Xtr = scaler.transform(Xtr).astype('float32')
Xte = scaler.transform(Xte).astype('float32')
print(Xtr.shape)

(7000, 3)

print(f'training rows: {Xtr.shape[0]:,}   predictors: {Xtr.shape[1]}')
print(f'base rate (share who default): {y.mean():.3%}')
print(f'always-predict-"no" accuracy:  {1 - y.mean():.3%}')

base rate (share who default): 3.330%

2. PyTorch model¶

Three dense layers, 3 -> 32 -> 32 -> 2, with ReLU between them and dropout at 0.2 on each hidden layer. Two points worth pausing on:

  • The last layer emits 2 raw scores (logits), not probabilities. nn.CrossEntropyLoss applies the softmax itself, so applying one here would apply it twice.

  • nn.Dropout is only active in training mode. model.eval() further down switches it off, which is why prediction is deterministic even though training is not.

try:
    import torch
    from torch import nn, optim
    from torch.utils.data import DataLoader, TensorDataset
    HAVE_TORCH = True
except Exception:
    HAVE_TORCH = False
    print('PyTorch not installed; pip install torch')

if HAVE_TORCH:
    torch.manual_seed(1)        # seed the weight init AND the loader shuffle below,
                                # so the AUC printed further down is reproducible
    class MLP(nn.Module):
        def __init__(self, p, k=32):
            super().__init__()
            self.net = nn.Sequential(
                nn.Linear(p, k), nn.ReLU(), nn.Dropout(0.2),
                nn.Linear(k, k), nn.ReLU(), nn.Dropout(0.2),
                nn.Linear(k, 2))
        def forward(self, x): return self.net(x)

    model = MLP(Xtr.shape[1])
    loss_fn = nn.CrossEntropyLoss()
    opt = optim.Adam(model.parameters(), lr=1e-3)

3. Training loop¶

Forty passes over the training set in mini-batches of 64. Each batch repeats the same four steps — the loop every PyTorch model is trained by:

opt.zero_grad() (clear last batch’s gradients, which PyTorch accumulates rather than overwrites) → forward pass → loss.backward() (backpropagation) → opt.step() (Adam updates every weight).

Then model.eval() turns dropout off and torch.no_grad() stops PyTorch building a graph for gradients it will never use.

if HAVE_TORCH:
    loader = DataLoader(
        TensorDataset(torch.tensor(Xtr), torch.tensor(ytr).long()),
        batch_size=64, shuffle=True)
    for epoch in range(40):
        for xb, yb in loader:
            opt.zero_grad()
            loss = loss_fn(model(xb), yb)
            loss.backward()
            opt.step()
    model.eval()
    with torch.no_grad():
        proba = torch.softmax(model(torch.tensor(Xte)), dim=1).numpy()[:, 1]
    from sklearn.metrics import roc_auc_score
    print('AUC:', round(roc_auc_score(yte, proba), 3))

AUC: 0.943

Reading the output. AUC 0.943 on held-out customers. Read it against the base rate printed in section 1: accuracy would have flattered a model that simply never predicts default, whereas AUC asks whether the model ranks a true defaulter above a non-defaulter, which is the question a credit team actually has.

4. Counting the parameters¶

Exercises 10.3 and 10.4 in the deck are done by hand. Both are worth checking in code, because the arithmetic is the part everyone gets wrong and PyTorch will tell you the truth in one line.

The rule for a dense layer is one weight per input–output pair plus one bias per unit:

\[\#\text{params} = n_{\text{in}}\, n_{\text{out}} + n_{\text{out}}.\]
if HAVE_TORCH:
    # Building layers draws random initial weights, and the worked solutions further
    # down are seeded — so put the global RNG back exactly as we found it at the end.
    _rng_state = torch.get_rng_state()

    def dense_params(n_in, n_out):
        """Trainable parameters in a dense layer (weights + one bias per unit)."""
        return n_in * n_out + n_out

    # Exercise 10.3: 10 inputs -> 32 -> 16 -> 3 softmax outputs.
    layers = [(10, 32), (32, 16), (16, 3)]
    by_layer = [dense_params(a, b) for a, b in layers]
    print('Ex 10.3 layer by layer:', ' + '.join(map(str, by_layer)), '=', sum(by_layer))

    deck_net = nn.Sequential(nn.Linear(10, 32), nn.ReLU(),
                             nn.Linear(32, 16), nn.ReLU(),
                             nn.Linear(16, 3))
    print('        PyTorch agrees:', sum(t.numel() for t in deck_net.parameters() if t.requires_grad))
    print('   the MLP trained above:', sum(t.numel() for t in model.parameters() if t.requires_grad))

    # Exercise 10.4: 32x32x3 image, 16 filters of 5x5, stride 1, no padding.
    conv = nn.Conv2d(in_channels=3, out_channels=16, kernel_size=5)
    n_conv = sum(t.numel() for t in conv.parameters())
    side = (32 - 5) // 1 + 1
    print(f'\nEx 10.4 conv output: {side}x{side}x16, parameters: {n_conv}')

    n_out = side * side * 16
    dense_equiv = 3 * 32 * 32 * n_out + n_out
    print(f'        a dense layer to the same {n_out:,} outputs: {dense_equiv/1e6:.1f} million '
          f'({dense_equiv // n_conv:,}x more)')
    print(f'        after 2x2 max-pool (stride 2): {side//2}x{side//2}x16, 0 parameters')

    torch.set_rng_state(_rng_state)

Ex 10.3 layer by layer: 352 + 528 + 51 = 931
        PyTorch agrees: 931
   the MLP trained above: 1250

Ex 10.4 conv output: 28x28x16, parameters: 1216
        a dense layer to the same 12,544 outputs: 38.5 million (31,700x more)
        after 2x2 max-pool (stride 2): 14x14x16, 0 parameters

Reading the output. 352 + 528 + 51 = 931, matching the deck, and PyTorch confirms it. The convolution needs 1216 parameters where a dense layer reaching the same 12,544 outputs would need 38.5 million — a factor of 31,700. That ratio is the argument for convolution: weight sharing, not depth, is what makes images tractable. Max-pooling adds no parameters at all; it only takes a maximum.

5. Does the network actually beat logistic regression?¶

A neural network is only worth its complexity if it beats the simpler model on held-out data. Default is the fairest possible test of that claim: three predictors, a boundary that Chapter 4 already showed is close to linear.

from sklearn.linear_model import LogisticRegression
from sklearn.metrics import roc_auc_score

logit = LogisticRegression(max_iter=1000).fit(Xtr, ytr)
auc_logit = roc_auc_score(yte, logit.predict_proba(Xte)[:, 1])
print(f'logistic regression AUC: {auc_logit:.3f}')

if HAVE_TORCH:
    auc_mlp = roc_auc_score(yte, proba)
    print(f'MLP AUC:                 {auc_mlp:.3f}')
    print(f'difference:              {auc_mlp - auc_logit:+.3f}')

logistic regression AUC: 0.946
MLP AUC:                 0.943
difference:              -0.003

Reading the output. The two are within a few thousandths of each other, and the logistic regression is the better model as a deliverable: three coefficients you can read on the odds scale, fitted in milliseconds, with standard errors. This is the honest result on tabular data of this size and shape, and it is the ISLP position too — deep learning earns its keep where the signal is structured (images, sequences, text), not by default on three columns of credit data. Section 4’s convolution arithmetic shows where that structure pays.

Lecture exercises — worked Python solutions¶

The [Python]-tagged exercises from the lecture slides, solved step by step. Exercise 10.6 is pure NumPy; Extended Exercise 10.3 needs a PyTorch runtime (guarded below, so the notebook still runs without torch).

Exercise 10.6 — Softmax and cross-entropy [Python]¶

A 3-class classifier outputs logits z = (2.0, 1.0, 0.1) for one observation whose true label is class 0. Compute the softmax probabilities and the cross-entropy loss.

import numpy as np

z = np.array([2.0, 1.0, 0.1])          # raw scores (logits)
z = z - z.max()                        # subtract max for numerical stability
p = np.exp(z) / np.exp(z).sum()        # softmax: turn logits into probabilities
ce = -np.log(p[0])                     # cross-entropy for the true class y=0
print("softmax p =", np.round(p, 3))   # -> [0.659 0.242 0.099]
print("cross-entropy =", round(ce, 3)) # -> 0.417
# The shift by z.max() does not change p (softmax is shift-invariant) but
# avoids overflow in exp(); CE = -log(prob assigned to the correct class).

softmax p = [0.659 0.242 0.099]
cross-entropy = 0.417

Reading the output. The model puts 0.659 on the correct class, so the loss −log(0.659) = 0.417 is small but non-zero. Cross-entropy only looks at the probability of the true class; it → 0 as that probability → 1 and blows up as it → 0.

Extended Exercise 10.3 — Overfitting and regularisation [Python]¶

Fit a PyTorch MLP to a deliberately tiny Default training set (n=200), watch it overfit, then tame it with weight decay (L2). Needs a torch runtime — runs on Colab out of the box.

try:
    import torch
    from torch import nn, optim
    HAVE_TORCH = True
except Exception:
    HAVE_TORCH = False
    print("PyTorch not installed - skipping (runs on Colab or after `pip install torch`).")

if HAVE_TORCH:
    import numpy as np
    from sklearn.preprocessing import StandardScaler
    from sklearn.model_selection import train_test_split

    Default = load("Default")                          # ISLP / local CSV / GitHub
    Default["y"]         = (Default["default"] == "Yes").astype(int)  # 0/1 response
    Default["student_d"] = (Default["student"] == "Yes").astype(int)  # dummy-code
    X = Default[["balance", "income", "student_d"]].astype(float).values
    Xtr, Xte, ytr, yte = train_test_split(
        X, Default["y"].values, train_size=200,        # deliberately tiny train set!
        random_state=0, stratify=Default["y"])
    sc = StandardScaler().fit(Xtr)                      # scale using TRAIN stats only
    Xtr, Xte = sc.transform(Xtr), sc.transform(Xte)
    Xtr, Xte = map(lambda a: torch.tensor(a, dtype=torch.float32), (Xtr, Xte))
    ytr, yte = map(lambda a: torch.tensor(a, dtype=torch.int64),   (ytr, yte))

    def curve(weight_decay, epochs=400):               # returns per-epoch losses
        torch.manual_seed(1)                           # reproducible weights
        net = nn.Sequential(nn.Linear(3, 128), nn.ReLU(),   # wide MLP, no dropout
                            nn.Linear(128, 128), nn.ReLU(),
                            nn.Linear(128, 2))
        loss_fn = nn.CrossEntropyLoss()                # softmax + log-loss in one
        opt = optim.Adam(net.parameters(), lr=1e-2,
                         weight_decay=weight_decay)     # L2 penalty lives here
        tr, va = [], []
        for _ in range(epochs):                        # full-batch gradient steps
            opt.zero_grad(); loss = loss_fn(net(Xtr), ytr)
            loss.backward(); opt.step()                # backprop + update
            with torch.no_grad():                      # eval: no gradients
                tr.append(loss.item())
                va.append(loss_fn(net(Xte), yte).item())
        return tr, va

    tr0, va0 = curve(0.0)                              # unregularised -> overfits
    tr1, va1 = curve(0.1)                              # strong weight decay (L2)
    print(f"unreg : train {tr0[-1]:.3f}  val-min {min(va0):.3f} "
          f"@ep {int(np.argmin(va0))}  val-final {va0[-1]:.3f}")
    print(f"decay : train {tr1[-1]:.3f}  val-final {va1[-1]:.3f}")
    # Typical: unreg train -> ~0 but val U-turns upward (overfitting);
    #          decay keeps val lower and flat. Early stopping = val minimum.

    # Two-curve overfitting diagnostic: train vs validation loss.
    fig, ax = plt.subplots(figsize=(6.5, 4))
    ax.plot(tr0, color="C3", label="train (no weight decay)")
    ax.plot(va0, color="C3", ls="--", label="val (no weight decay)")
    ax.plot(tr1, color="C0", label="train (weight decay 0.1)")
    ax.plot(va1, color="C0", ls="--", label="val (weight decay 0.1)")
    ax.axvline(int(np.argmin(va0)), color="C3", lw=0.8, ls=":", alpha=0.7,
               label="early-stop (val min)")
    ax.set_xlabel("epoch"); ax.set_ylabel("cross-entropy loss")
    ax.set_title("Training vs validation loss: overfitting vs weight decay")
    ax.legend(fontsize=8, ncol=2); plt.tight_layout(); plt.show()

unreg : train 0.002  val-min 0.096 @ep 16  val-final 0.934
decay : train 0.186  val-final 0.183

Reading the output. Without regularisation the training loss collapses toward 0 (the 128-128 net memorises the 200 points) while the validation loss bottoms out early and then climbs — textbook overfitting. Weight decay keeps the validation loss lower and flat, trading a little training fit for much better generalisation; early stopping at the validation minimum is a free alternative regulariser.
