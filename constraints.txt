# =============================================================================
# constraints.txt -- the build that reproduces the shipped notebook outputs
# =============================================================================
#
# WHAT THIS IS
#   requirements.txt says what the labs *need* (deliberately loose, so the course
#   keeps working as the ecosystem moves). This file records the one build that
#   was verified to reproduce the outputs currently stored in
#   Chapters/*.ipynb. It is a record, not a requirement.
#
# HOW TO USE IT
#   Normal use -- take the current ecosystem, nothing here applies:
#       pip install -r requirements.txt
#
#   Reproduce the stored outputs exactly (e.g. a number in a notebook disagrees
#   with what your machine prints, and you want to know whether the notebook is
#   wrong or your stack has moved):
#       pip install -r requirements.txt -c constraints.txt
#
#   A constraints file only caps versions of packages that are being installed
#   anyway; it never pulls anything in on its own. `jupyter` and its dependencies
#   are intentionally absent -- the notebook front end does not affect results.
#
# WHAT WAS VERIFIED (2026-08-04)
#   Python 3.9.6 (macOS, arm64), ISLP installed. All 25 notebooks -- 12 chapter
#   labs, 7 advanced-module labs, 6 project starters -- executed top to bottom in
#   a fresh kernel: 0 cell errors, 0 drifted cells against the stored outputs
#   (`make notebooks`). Every substantive number, table and summary reproduced
#   exactly. chapter_00 and chapter_00b reproduce cell-for-cell, including figure
#   bytes.
#
#   Two stored outputs were refreshed on this date because they had been captured
#   on a machine WITHOUT ISLP and so showed the CSV-fallback branch rather than the
#   real analysis: chapter_12 cell 14 (the NCI60 clustering crosstab, previously an
#   "NCI60 ships only with the ISLP package" message) and advanced_06_survival
#   cell 1 (BrainCancer head() -- ISLP's 0-based RangeIndex, where the CSV route
#   had produced 1-based row labels). No published number changed in either; the
#   decks quote neither output.
#
#   The only remaining differences anywhere are:
#     * statsmodels / lifelines banners that print the current date and time
#       (chapters 3, 4, 7, 11) -- unavoidable, not drift;
#     * occasional cells where identical stdout arrives in two chunks rather than
#       one. This is a kernel flush-boundary artefact, not a change in output:
#       compare stream outputs concatenated, not object by object.
#
#   Note for anyone diffing stored against fresh output: chapter_07 surfaces
#   pyGAM's p-value caveat on stderr twice, by design, and it IS stored, so the
#   caveat is visible in the rendered docs as the prose promises. The message body
#   is stable, but the location prefix in front of it is not: pyGAM warns with
#   stacklevel=2, so the prefix names the ipykernel temp file for the cell, whose
#   path carries the kernel PID and a per-cell hash
#   (/var/folders/.../T/ipykernel_66177/3808341760.py:6:). Normalise that prefix
#   before comparing; do NOT normalise the message text, or the check stops
#   detecting the real changes it exists to catch.
#
#   These two are the only stored outputs in any of the 25 notebooks that contain
#   a filesystem path, and it is unavoidable: Python's warning machinery prints
#   the filename of the code that raised the warning, which for notebook-level
#   code is always the kernel's temp file. The path holds no username or project
#   name -- just macOS's opaque per-user temp hash -- and a student running the
#   lab sees their own equivalent.
#
# WHY ONLY TWO PACKAGES ARE PINNED IN requirements.txt
#   Results proved insensitive to the rest of the stack, so freezing all of it
#   would cost more than it buys. Cross-checked on Python 3.11 with numpy 2.4.6
#   and scipy 1.16.3: the chapter 7 GAM still reports AIC 49773.6924, i.e. three
#   years of numpy/scipy movement changed nothing. Two packages are the exception
#   and are pinned in requirements.txt, not merely recorded here:
#
#     * pygam -- the one package measured to move a published number. 0.12.0
#       changed the likelihood/AIC computation: chapter 7 reports AIC 30643.72
#       rather than 49773.69 and log-likelihood -15299.66 rather than -24864.65.
#       Python 3.9 resolves `pygam>=0.9` to 0.10.1 regardless, but Python 3.10+
#       (Colab included) resolves it to 0.12.0 -- so the stored chapter 7 numbers
#       had quietly stopped matching for anyone on a current interpreter.
#
#     * ISLP -- unpinned it spanned 0.3.1 to 0.4.1, across which load_data() does
#       not return consistent dtypes. Pinned to the version verified above.
# =============================================================================
